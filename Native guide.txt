3. MOBILE ARCHITECTURAL & WEB PARITY DOMAIN GROUPING
--------------------------------------------------------------------------------

1. Web App vs. Mobile App Flow & Grouping Parity:
   - Web App (scancode-web) groups pages under /login, /store/[slug], /checkout, /admin/dashboard, /frontdesk, and /superadmin.
   - Mobile Best Practice structures React Native screen files into domain subfolders:
     * src/screens/(auth)/       <-- Authentication & Onboarding
     * src/screens/(customer)/   <-- Customer Storefront, Checkout & Scanner
     * src/screens/(admin)/      <-- Merchant POS, Live Orders, Charges & Bank Settings

4. MOBILE-NATIVE UNIQUE SCREENS & HARDWARE FEATURES [CHECK]
--------------------------------------------------------------------------------

1. Native Camera QR & Barcode Scanner (CameraQRScannerScreen):
   - Direct integration using 'expo-camera'.
   - Features continuous auto-focus, haptic vibration on successful scan, LED flash toggle, 
     manual code input fallback, and auto-navigation to table storefronts.

2. Push Notifications & Background Order Audio Alarms (audioAlert & FCM):
   - Integration with FCM / Expo Notifications & Web Audio synthesis.
   - Triggers continuous loud audio alarms when a new order arrives, even when the app 
     is running in the background or the screen is locked.

3. ESC/POS Thermal Receipt Printer Integration (PrintReceiptScreen):
   - Direct Bluetooth / USB POS thermal receipt printing for kitchen order tickets (KOT) 
     and customer receipts straight from mobile devices.

4. Biometric Quick Login & Staff Switch (LocalAuthScreen):
   - Quick unlock using 'expo-local-authentication' (Face ID / Touch ID / Fingerprint) 
     for fast staff context switching on shared POS tablets/phones.

5. Native Camera & Photo Picker for Menu Editing (expo-image-picker):
   - Direct camera photo capture and device photo library picker for merchants uploading 
     dish images directly to ProductCatalogEditorScreen.

6. Haptic Feedback & Micro-Interactions (expo-haptics):
   - Tactile vibration triggers on button taps, order updates, success events, and swipe actions.

7. Native Modal Bottom Sheets (@gorhom/bottom-sheet):
   - Slide-up bottom sheets replacing web dialog popups for item customization options, 
     quick cart drawer previews, and category filters.

8. Swipe-to-Action Order Cards (SwipeableOrderCard):
   - Gesture-driven swipe right (Confirm) and swipe left (Reject) actions for incoming orders.

9. Offline Mode & Local Storage Sync (SQLite / AsyncStorage):
   - Caching menu items and queueing offline order actions when network connectivity drops 
     in busy venue dead zones.

10. Geofencing & Location-Based Store Auto-Detection (expo-location):
    - Uses GPS/Geofencing to auto-detect when a customer enters a venue and launch the 
      storefront menu automatically without requiring a manual QR scan.

[2026-08-19 — how each of the above was actually resolved, see AGENTS.md change log for full detail:
 - VAT: StoreConfigResponse.vatRate was stored inconsistently (fraction on save, raw
   percent in seed/fallback data). CheckoutScreen was the one consumer that didn't
   normalize it, so it was computing VAT as 750% of subtotal instead of 7.5% on any
   default/seeded storefront. Fixed the seed/fallback data at the source and added the
   missing normalization guard to CheckoutScreen.
 - Custom Notification Tones: the feature was silently dead because it depended on
   expo-av, which was fully removed from the Expo SDK at version 55 (this project is on
   57). Migrated src/utils/audioAlert.ts to expo-audio; custom tones now play on native
   AND web (expo-audio has real web support, unlike the old setup).
 - Weekly events per storefront: verified (grepped every read/write site) that events
   were already strictly isolated by storefrontId in both the demo layer and the API
   contract — no cross-storefront leakage existed. Built EventsManagerScreen as the
   missing admin CRUD UI on top of that already-correct isolation.]
