3. MOBILE ARCHITECTURAL & WEB PARITY DOMAIN GROUPING
--------------------------------------------------------------------------------

1. Web App vs. Mobile App Flow & Grouping Parity:
   - Web App (scancode-web) groups pages under /login, /store/[slug], /checkout, /admin/dashboard, /frontdesk, and /superadmin.
   - Mobile Best Practice structures React Native screen files into domain subfolders:
     * src/screens/(auth)/       <-- Authentication & Onboarding
     * src/screens/(customer)/   <-- Customer Storefront, Checkout & Scanner
     * src/screens/(admin)/      <-- Merchant POS, Live Orders, Charges & Bank Settings

2. Mobile UX Rule of 5 & Task-Based Navigation Grouping: [CHECK]
   Instead of loose screen lists, group merchant services into 4 primary Bottom Navigation Tabs:

   📱 Admin Mobile Navigation Hub (BottomTabNavigator)
   ├── 🛍️ Tab 1: Orders (HIGH FREQUENCY - Real-time Live Operations)
   │    ├── Live Incoming Orders (Confirm / Reject / Cancel)
   │    └── Waiter & Assistance Calls
   │
   ├── 🍔 Tab 2: Catalog (MEDIUM FREQUENCY - Daily Stock & Menu)
   │    ├── Product & Stock Management
   │    ├── Category Tagger
   │    └── Store Gallery Photos
   │
   ├── 🔔 Tab 3: Activity (MEDIUM FREQUENCY - Customer Engagement)
   │    ├── Tip & Request Payment Acknowledgements
   │    ├── Weekly Events Schedule
   │    └── Customer Ratings & Feedback
   │
   └── ⚙️ Tab 4: Settings (LOW FREQUENCY - Setup & Admin)
        ├── VAT Rate % & Delivery Fee Toggle
        ├── Table QR Generator & Activation
        └── Merchant Bank Payout Profile

4. MOBILE-NATIVE UNIQUE SCREENS & HARDWARE FEATURES [CHECK]
--------------------------------------------------------------------------------

1. Native Camera QR & Barcode Scanner (CameraQRScannerScreen):
   - Direct integration using 'expo-camera'.
   - Features continuous auto-focus, haptic vibration on successful scan, LED flash toggle, 
     manual code input fallback, and auto-navigation to table storefronts.

2. Push Notifications & Background Order Audio Alarms (audioAlert & FCM):
   - Integration with FCM / Expo Notifications & Web Audio synthesis.
   - Triggers continuous loud audio alarms when a new order arrives, even when the app 
     is running in the background or the screen is locked.

3. ESC/POS Thermal Receipt Printer Integration (PrintReceiptScreen):
   - Direct Bluetooth / USB POS thermal receipt printing for kitchen order tickets (KOT) 
     and customer receipts straight from mobile devices.

4. Biometric Quick Login & Staff Switch (LocalAuthScreen):
   - Quick unlock using 'expo-local-authentication' (Face ID / Touch ID / Fingerprint) 
     for fast staff context switching on shared POS tablets/phones.

5. Native Camera & Photo Picker for Menu Editing (expo-image-picker):
   - Direct camera photo capture and device photo library picker for merchants uploading 
     dish images directly to ProductCatalogEditorScreen.

6. Haptic Feedback & Micro-Interactions (expo-haptics):
   - Tactile vibration triggers on button taps, order updates, success events, and swipe actions.

7. Native Modal Bottom Sheets (@gorhom/bottom-sheet):
   - Slide-up bottom sheets replacing web dialog popups for item customization options, 
     quick cart drawer previews, and category filters.

8. Swipe-to-Action Order Cards (SwipeableOrderCard):
   - Gesture-driven swipe right (Confirm) and swipe left (Reject) actions for incoming orders.

9. Offline Mode & Local Storage Sync (SQLite / AsyncStorage):
   - Caching menu items and queueing offline order actions when network connectivity drops 
     in busy venue dead zones.

10. Geofencing & Location-Based Store Auto-Detection (expo-location):
    - Uses GPS/Geofencing to auto-detect when a customer enters a venue and launch the 
      storefront menu automatically without requiring a manual QR scan.

5. RECOMMENDED MOBILE UX & AESTHETIC ENHANCEMENTS FOR FUTURE IMPLEMENTATION [CHECK]
--------------------------------------------------------------------------------

1. Glassmorphic Cards & Elevated Depth Design System:
   - Implement semi-transparent frosted glass cards (rgba(255, 255, 255, 0.85) with backdropBlur) 
     for checkout summaries, order status cards, and float action bars.
   - Use soft dual-tone gradients (#6C63FF to #4F46E5) for active buttons and accent elements.

2. High-Contrast OLED Dark Mode for Kitchen & POS Terminals:
   - Build an OLED pitch-black dark theme (#09090B card background, #18181B borders) 
     specifically for kitchen display systems (KDS) to eliminate screen glare and reduce battery draw.

3. Micro-Animations & Fluid Spring Transitions:
   - Add spring physics (using react-native-reanimated) when items are added to the cart, 
     causing the cart floating badge to bounce dynamically.
   - Animated status badge state transitions (Pending amber glow pulse -> Confirmed green pop).

4. Skeleton Loading Shimmers:
   - Replace standard ActivityIndicator spinners on Storefront and Dashboard with animated 
     skeleton loading card shimmers to make loading feel instant.

5. Tactile Haptic Pulses:
   - Trigger heavy haptic vibration on incoming new order alarms, medium haptic tap on order
     confirmation, and light haptic tick on category selection.

6. POST-PARITY FEATURE ADDITIONS (beyond the original 23-screen web-parity target)
--------------------------------------------------------------------------------
Added 2026-08-31. These have no equivalent in scancode-web, so they sit outside the
parity table in Section 1 — tracked here instead.

1. ServicesScreen (src/screens/(admin)/ServicesScreen.tsx) [COMPLETED]
   - Entry hub for vendors: "Create Storefront" (no storefronts yet) / "Add Storefront"
     (already has ≥1) card, plus an "Access Page" card. Tapping Access Page with multiple
     storefronts opens an inline picker; with exactly one, it navigates straight through.

2. AccessPageManagerScreen (src/screens/(admin)/AccessPageManagerScreen.tsx) [COMPLETED]
   - Per-storefront event page CRUD. Type picker (Custom / Wedding / Conference-Summit /
     Concert) — the three presets auto-populate a fixed field set (see demoEngine.ts's
     presetFields equivalent in the screen itself); Custom starts blank and fields are
     built one at a time (label, type: text/number/date/yesno/dropdown, required,
     dropdown options). Each page gets a shareable slug, an active/inactive toggle, a
     guest list (expandable, shows submitted responses + check-in time), and delete.

3. AccessPageGuestScreen (src/screens/(customer)/AccessPageGuestScreen.tsx) [COMPLETED]
   - Public, unauthenticated guest-facing screen reached via an access page's slug
     (`AccessPageGuest: { accessPageSlug }`). Renders the page's dynamic form, submits a
     guest entry, then reveals `exclusiveContent` (if set) as the check-in reward.
     Registered in AuthNavigator, AdminNavigator, and CustomerNavigator so it's reachable
     whether or not the visitor has an account — deliberately not gated behind login,
     matching how QR-scan ordering is anonymous-only.

4. StorefrontDirectoryScreen (src/screens/(customer)/StorefrontDirectoryScreen.tsx) [COMPLETED]
   - Post-login landing screen for logged-in customers (CustomerNavigator's initial
     route) and reachable from the Dashboard's Compass icon for vendors. Lists all
     published storefronts (getAllStorefronts), sortable by rating (getStorefrontRatings
     aggregation), location, or alphabetical. When the viewer is a vendor, their own
     storefronts render pinned above the full list. Has its own back button
     (navigation.canGoBack()) since it runs with a hidden native header in both
     navigators it's pushed into.

5. Nigeria location picker (CreateStorefrontScreen.tsx) [COMPLETED]
   - @react-native-picker/picker, backed by NIGERIA_STATES (36 states + FCT) in types.ts.
     Required field; persisted into storefront.data.location, read back via
     parseStorefrontData for both the directory's location sort and card display.

6. demoEngine.ts data layer for all of the above [COMPLETED]
   - Product CRUD (createProduct/updateProduct/deleteProduct), storefront directory
     (getAllStorefronts — published-only, distinct from getMyStorefronts), ratings
     aggregation (getStorefrontRatings, seeded from a new feedbacks store), and full
     Access Page CRUD + guest check-in, all persisted through AsyncStorage with the same
     conventions as the rest of the file (KEYS map, simulateLatency, reset/init coverage).

[2026-08-19 — how each of the above was actually resolved, see AGENTS.md change log for full detail:
 - VAT: StoreConfigResponse.vatRate was stored inconsistently (fraction on save, raw
   percent in seed/fallback data). CheckoutScreen was the one consumer that didn't
   normalize it, so it was computing VAT as 750% of subtotal instead of 7.5% on any
   default/seeded storefront. Fixed the seed/fallback data at the source and added the
   missing normalization guard to CheckoutScreen.
 - Custom Notification Tones: the feature was silently dead because it depended on
   expo-av, which was fully removed from the Expo SDK at version 55 (this project is on
   57). Migrated src/utils/audioAlert.ts to expo-audio; custom tones now play on native
   AND web (expo-audio has real web support, unlike the old setup).
 - Weekly events per storefront: verified (grepped every read/write site) that events
   were already strictly isolated by storefrontId in both the demo layer and the API
   contract — no cross-storefront leakage existed. Built EventsManagerScreen as the
   missing admin CRUD UI on top of that already-correct isolation.]
